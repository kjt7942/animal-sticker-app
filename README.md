# 동물 스티커 도감

사진 속 동물을 인식해서 배경을 오려낸 스티커로 만들고, 20종 도감으로 수집하는 웹 앱. 순수 정적 사이트(HTML/CSS/JS, 빌드 도구 없음)로, GitHub Pages 배포를 전제로 만들었다.

## 목적

"Gotcha: Animal Identifier" 같은 앱을 참고해서, 동물 사진을 찍으면 스티커로 만들고 도감처럼 모으는 기능을 최소 비용으로 구현하는 연습 프로젝트. 핵심 제약은 **LLM 비전 API를 쓰지 않는 것** — 인식과 컷아웃 둘 다 온디바이스 모델로 처리해서 사용자가 아무리 늘어도 토큰 비용이 늘지 않는 구조를 목표로 했다.

## 최초 기획 스크립트

프로젝트 시작 시 작성한 기술 스펙(`animal-sticker-app-spec-android.md`)의 핵심 설계 원칙:

> **LLM(Claude/GPT 등 비전 API)은 최후의 수단으로만 쓴다.** 파이프라인의 기본 경로는 100% 온디바이스 또는 자체 호스팅 경량 모델로 처리하고, 자신 없는 케이스에서만 저렴한 비전 모델을 호출한다.
>
> 두 가지 서로 다른 문제를 반드시 분리해서 생각할 것:
> 1. **컷아웃(세그멘테이션)** — "사진에서 피사체만 깔끔하게 오려내기". LLM이 할 일이 아니다.
> 2. **종 인식(분류)** — "이게 무슨 생물인지 맞추기". 전용 분류 모델이 LLM보다 정확하고 저렴하다.

원래 스펙은 갤럭시 S25(Android 네이티브, ML Kit + TFLite + Room)를 타깃으로 작성했지만, 실제 구현은 빌드 환경 없이 바로 돌려볼 수 있는 **웹 프로토타입**으로 방향을 바꿔 진행했다. "LLM 없이 온디바이스로 처리한다"는 원칙만 그대로 가져오고, ML Kit 대신 브라우저에서 돌아가는 TensorFlow.js 기반 모델로 대체했다.

## 구현한 주요 기능

- **동물 인식**: TensorFlow.js MobileNet(ImageNet 1000종 사전학습)을 브라우저에서 그대로 로드해 분류. ImageNet 클래스명을 한글 이름으로 매핑하는 테이블(`js/animals.js`)을 직접 만들어 약 150개 클래스를 커버.
- **20종 도감 + 야생 발견**: 도감에 등록된 20종은 여러 ImageNet 클래스를 alias로 묶어 하나의 슬롯으로 수집(`js/animals.js` SPECIES). 도감 밖 동물이 인식되면 "야생 발견"으로 별도 수집.
- **배경 제거(스티커화)**: `@imgly/background-removal`(온디바이스 세그멘테이션 모델, WebGPU 우선/실패 시 CPU 폴백)로 매팅한 뒤, 직접 짠 알고리즘으로 후처리:
  - 커넥티드 컴포넌트로 배경 찌꺼기(방충망·풀숲 등 흐릿한 잔여물) 제거
  - 피사체가 작게 찍혔을 때 얇은 부위(다리·더듬이·뿔)가 배경으로 잘리는 문제를 크롭 후 재매팅으로 보정
  - 체임퍼 거리 변환으로 실루엣을 따라 균일한 흰 테두리를 두르는 스티커 마감
- **꾸미기**: 스티커에 이모지 데코(하트/별/반짝/꽃)와 텍스트 캡션(Jua 폰트) 추가, PNG로 저장/공유(Web Share API, 미지원 시 다운로드 폴백).
- **로컬 도감 저장**: IndexedDB에 발견 기록(sightings)을 쌓고, 발견 횟수/최초 발견일/대표 사진을 매번 기록에서 계산(별도 카운터를 두지 않아 동기화 버그 자체가 안 생기는 구조).
- **오늘의 발견**: 하루 1마리 신규 발견 시 완료 표시(localStorage).
- **PWA**: 서비스워커로 앱 셸 캐싱(네트워크 우선) + 모델 파일(수십 MB) CDN 캐싱(캐시 우선), 홈 화면 설치 지원.

## 화면 흐름

```
촬영/앨범 선택
   │
   ▼
downscale (장축 1280px)
   │
   ▼
MobileNet 분류 → 한글 이름 매핑 → 후보 3개 칩 표시
   │
   ├─ 이름 확인/수정 (직접 고르기 목록도 가능)
   │
   ▼
[선택] 스티커로 변환 → 배경 제거 + 테두리
   │
   ▼
도감에 추가 → IndexedDB 저장 → 발견 모달 → 도감 그리드 갱신
```

도감 카드 클릭 → 상세 모달(사진 목록/대표 사진 지정/삭제/스티커 크게 보기/꾸미기).

## 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 실행 환경 | 정적 HTML/CSS/JS (모듈, 빌드 없음) | 로컬에서 바로 열거나 GitHub Pages에 그대로 올리면 끝 |
| 동물 인식 | TensorFlow.js + `@tensorflow-models/mobilenet` (CDN) | 온디바이스, API 호출 없음 → 비용 0 |
| 배경 제거 | `@imgly/background-removal` (CDN, WebGPU/WASM) | 온디바이스 세그멘테이션, ML Kit의 웹 대응 |
| 저장 | IndexedDB (스티커 Blob) + localStorage (오늘의 발견) | Blob은 IndexedDB에만 저장 가능 |
| PWA | Service Worker + Web App Manifest | 홈 화면 설치, 모델 재다운로드 방지 |
| 폰트 | Google Fonts (Jua, Gaegu) | 도감/스티커 캐주얼 톤 |

## 요구 사항 / 실행 방법

빌드 과정 없음. `index.html`을 정적 서버로 서빙하면 된다(서비스워커·카메라 권한 때문에 `file://` 직접 열기보다는 로컬 서버 권장, 예: `npx serve` 또는 VS Code Live Server). 인터넷 연결 필요(MobileNet·배경 제거 모델을 CDN에서 최초 1회 다운로드, 이후 서비스워커가 캐싱).

## 트러블슈팅 · 배운 점

- **`img.decode()`가 브라우저에 따라 이미 그려진 이미지에도 `EncodingError`를 낸다** → 화면의 `<img>` 요소 대신 `createImageBitmap` + 캔버스로 분류 입력을 만들도록 변경(`js/app.js:119-121`).
- **작은 피사체의 얇은 부위(다리·더듬이·뿔)가 매팅 모델에서 통째로 배경 판정됨** → 매팅 모델 입력이 1024×1024로 고정이라 피사체가 화면을 작게 채울수록 디테일이 죽는다는 게 원인. 1차 결과에서 피사체 바운딩박스를 구해 그 영역만 크게 잘라 2배 이상 확대한 뒤 재매팅하는 `refineByCrop`으로 해결(`js/sticker.js:174-202`).
- **배경 제거 결과에 방충망·풀숲 같은 배경 찌꺼기가 흐릿한 덩어리로 남아 스티커를 망침** → 알파값이 진하게 남은(>128) 픽셀만 커넥티드 컴포넌트로 묶고, 가장 큰 덩어리의 25% 이상인 것만 살리는 방식으로 필터링(`js/sticker.js:100-172`).
- **GitHub Pages는 커스텀 HTTP 헤더를 못 넣어 WASM 멀티스레드(SharedArrayBuffer)를 못 켬** → 단일 스레드 CPU 매팅은 12초 이상 걸려서, WebGPU를 지원하면 우선 시도하고 실패 시에만(한 번 실패하면 이후 요청은 아예 재시도 없이) CPU로 폴백(`js/sticker.js:56-68`).
- **실루엣 테두리를 여러 방향으로 겹쳐 그리면 다리·더듬이 둘레가 울퉁불퉁해짐** → 체임퍼 거리 변환(2-pass)으로 각 픽셀에서 실루엣까지의 최단 거리를 구해 균일한 두께의 테두리를 그리는 방식으로 교체(`js/sticker.js:70-98, 204-250`).
- **발견 횟수/최초 발견일을 별도 필드로 캐싱하면 도감 데이터와 어긋날 위험** → 두 값 다 IndexedDB의 발견 기록(sightings)에서 매번 재계산하고, 계산 불가능한 값(오늘의 발견 여부)만 localStorage에 둠(`js/storage.js:1-7`).

## 향후 계획

- 사슴벌레·장수풍뎅이는 ImageNet에 아예 없는 클래스라 자동 인식이 절대 안 됨 — "직접 고르기"로만 등록 가능한 상태(`js/animals.js:67-68`). 필요하면 곤충 전용 분류 모델을 추가하거나 스펙 문서의 iNaturalist 전이학습 방향으로 교체 검토.
- 스펙 문서에 있던 3단계 LLM 폴백(신뢰도 낮을 때만 저가 비전 모델 호출)은 아직 미구현 — 현재는 MobileNet 신뢰도가 낮으면 바로 "동물을 찾지 못했어요"로 처리(`js/app.js:141-145`).
- 자동화된 테스트 없음.
- Android 네이티브 전환(ML Kit + Room)은 스펙만 존재하고 실제 구현은 웹 버전으로 대체된 상태.
